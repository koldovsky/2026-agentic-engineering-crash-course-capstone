## Problems

- [x] P-001 [design-review] `demo/modules/test/application/InitUseCase.php:47` - hardcoded module id instead of being given it
  Severity: error. Rule: E (AGENTS.md rule 6) / D-DIP.
  `InitUseCase::handle()` does `$serviceName = new ServiceName('test')` - hardcodes the module id instead of being
  given it. AGENTS.md rule 6: "Do not assume a fixed module ID ... use `Module::getInstance()` ... so the host can
  override components." `V1Controller`/`BaseController` already resolve the service name from `$this->module->id`
  (via `BaseController::serviceName()`) but never pass it down; `InitUseCase` independently re-derives (and
  hardcodes) it.
  Suggested fix: pass the service/module name into `InitUseCase::handle()` as a parameter (e.g. a `ServiceName` or
  plain module-id string the controller gets from `$this->module->id`), or inject it as a constructor value bound in
  `Module::bootstrap()`. Never a literal in application code.
  Fixed in iteration 1: `InitUseCase::handle()` now takes a `ServiceName $serviceName` parameter; `V1Controller`
  builds it from `$this->module->id` and passes it in. Updated `InitUseCaseTest`'s 6 call sites to match. Verified
  live (`POST /test/v1/init` → 200 success) and via the new functional test (P-003).

- [x] P-002 [design-review] `demo/domain/service/ServiceName.php:13` - regex allows `-`, contract says it must not
  Severity: error. Rule: E (AGENTS.md "Modules").
  `ServiceName::PATTERN = '/^[a-z][a-z0-9_-]*$/'` allows `-`, but AGENTS.md defines the module id (= service name) as
  `[a-z][a-z0-9_]*` and explicitly states "no `-`, it is a namespace segment". The divergence is deliberate, not an
  oversight: `demo/tests/Unit/domain/service/ServiceTest.php:17` asserts `pay-v2` is a *valid* ServiceName.
  Suggested fix: tighten the regex to `/^[a-z][a-z0-9_]*$/` (drop `-`) to match the documented module-id contract,
  and update `ServiceTest` accordingly (replace `pay-v2` with an underscore example).
  Fixed in iteration 1: regex tightened to `/^[a-z][a-z0-9_]*$/`, error message updated. `ServiceTest` now rejects
  `pay-v2` and uses `pay_v2` as the accepted example instead.

- [x] P-003 [design-review] `demo/tests/Functional/` - no functional tests for the `test` module's init/callback flow
  Severity: error (test coverage). Rule: G.
  Only `_bootstrap.php` exists under `demo/tests/Functional/`. AGENTS.md ("tests must cover success and fail") and
  `docs/architecture/code-design.md` §5 require functional coverage of every success/fail/error path through the
  real API <-> emulator wiring; only unit tests with fakes exist for module `test`.
  Suggested fix: add functional test(s) under `demo/tests/Functional/` that call `/test/v1/init` and
  `/test/v1/callback` against the emulator, covering success, fail and error (signature, status mapping,
  callback-before-init 404, etc. end-to-end - not just unit-level).
  Fixed in iteration 1: `demo/tests/Functional/TestModuleCest.php` added (6 cases, real HTTP through the real
  API<->emulator wiring, not fakes): init success, 422 missing field, 422 duplicate requestId, 405/wrong-verb, 404
  unknown callback id, 400 empty callback body. Required fixing `config/test.php` (was the unmodified skeleton
  default - no module registration, no container/queue wiring - `test/v1/init` would have 404'd) to build on
  `web.php` instead, and `config/test_db.php` (pointed at a never-provisioned `yii2basic_test`/`localhost` db) to
  reuse the real `demo` database (no separate test db exists in `docker/mysql/init/`; tests clean up their own rows).
  Added dev dependency `codeception/module-rest` (needed for JSON response assertions) and enabled it in
  `Functional.suite.yml`. All 6 pass. **Not covered**: the remote "fail" outcome and the exact callback-before-init
  race - the emulator's live endpoint always answers its default scenario (`Complete`, no scenario-selection decided
  yet - module.service.md §10, an existing open point, not something this fix invented a decision for).
